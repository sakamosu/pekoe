# pekoe voice 企画書

> pekoe に「声」を足す。エージェントの状態を tapi が喋って知らせ、必要なときは本文も読み上げる。

- ステータス: 企画(要件の引き継ぎ用)
- 対象リポジトリ: `sakamosu/pekoe`
- 関連: 外部 backend `pekoe-voice-voicevox`(pekoe 本体の外で配布)
- 対応 OS: 当面 macOS のみ

---

## 1. 背景

pekoe ではエージェントを並列で動かすのが前提になる。そのぶん「どのセッションが確認待ちか」「どれが終わったか」を知るために、画面を見に行く回数が増える。

画面を見ていないときでもエージェントの様子がわかれば、確認待ちで放置される時間が減る。レビューや別作業に集中しながら並列のエージェントを回すこともできる。

音で知らせる方法としては、Claude Code の hooks から `say` などを呼ぶやり方がすでに知られている。ただ、セッションが複数あると次の問題が出る。

- 複数のセッションが同時に喋って声が重なる
- どのセッションの話なのかわからない
- 見ていないセッションの長文まで読まれてうるさい

これらを解決するには「今どのセッションを見ているか」「各セッションがどの状態か」がわかっている必要がある。その情報を持っているのは pekoe なので、独立したツールではなく pekoe の機能として実装する。

## 2. 目的

1. **気づける**: 画面を見ていなくても、確認待ち・完了・エラーに気づける
2. **うるさくない**: 喋る量を、セッションへの注目度に応じて変える
3. **tapi の存在感**: 各セッションを見守る相棒という tapi の役割を、声で体験として成立させる

まずは Mac のスピーカーで鳴らすことに絞る。iPhone 用 Web UI での再生は、Mac で試して手応えを見てから検討する(§14)。

## 3. やらないこと

- 音声入力(マイクは使わない)
- 音声合成エンジンを pekoe 本体に組み込むこと。合成は外部 backend に任せる
- コードブロック・diff・表などの読み上げ
- 喋る内容を LLM で生成すること(初期は定型文。要約は将来の任意機能)
- iPhone 用 Web UI での再生(当面は Mac のみ。§14)
- Linux 対応(`espeak-ng` の日本語は実用的な品質ではないため、当面は対象外)

## 4. モード

声の出し方は 3 段階。セッションごとに、voice policy(§6.3)で決まる。

| モード | 内容 | 想定する場面 |
|---|---|---|
| **narrate** | tapi が状態の変化だけを短く喋る | 既定。裏で動いているセッション全般 |
| **read** | アシスタントの本文を読み上げる(コード等は除く)。状態の変化も narrate と同じく喋る | 今見ているセッション、または明示的に指定したセッション |
| **mute** | 喋らない | 集中したいとき、会議中など |

### 4.1 narrate(最初に作る)

**きっかけは pekoe 内部の状態遷移**(work / wait / done / error)とする。Claude Code の hook を直接のきっかけにはしない。状態検知の方式が何であっても、narrate はその結果を購読するだけにする。

セッションの呼び名を必ず頭に付けて、どのセッションの話かわかるようにする。番号で呼ぶ場合は、TUI に表示している番号と一致させる。

| 状態遷移 | 発話の例(ja) | 発話の例(en) |
|---|---|---|
| → wait | 「2番、確認待ちだよ」 | "Number 2 needs you." |
| → done | 「2番、終わったよ」 | "Number 2 is done." |
| → error | 「2番でエラーが出たみたい」 | "Number 2 hit an error." |
| 動いているセッションがなくなった | 「みんな手が空いたよ」 | "Everyone's idle." |

- 文言は tapi の口調で統一する。既定の文言は英語と日本語の両方を持ち、言語設定で切り替える。設定ファイルで上書きもできる
- 同じ種類の通知が短時間に続いたらまとめる(例:「2番と4番が確認待ちだよ」)
- 「動いているセッションがなくなった」は、work のセッションが 1 つ以上ある状態から 0 になったときに 1 回だけ喋る

### 4.2 read(第 2 段階)

- **受け取る**: `MessageDisplay` hook で、本文が画面に流れるのと同時に受け取る。この hook が使えない場合(§6.2 の検証結果、または Claude Code のバージョンが古い場合)は、`Stop` hook の `last_assistant_message` をターンの終わりにまとめて読む方式に落とす
- **読む範囲**:
  - コードブロック、表、URL、ファイルパスは読まない。Markdown の記号は取り除く
  - 長いメッセージは、先頭の N 文だけ読むか、要約(将来)で済ませる
- **止める**:
  - ユーザーが入力したら読み上げを止める(`UserPromptSubmit`)
  - フォーカスを別のセッションに移したら止める

## 5. 体験の要件

- 喋るのは同時に 1 つだけ(キューの決まりは §6.4)
- 状態が変わってから 1 秒以内に喋り始める(キャッシュ済みの定型文の場合)
- 止める・ミュートする操作は 1 キーでできる(TUI のキー割り当ては既存の UI ガイドラインに合わせる)
- 喋っている間、下部バーの tapi の表示を「喋っている」状態にする(表情を増やすかどうかは未決事項)
- 発話のログを残し、TUI で文字でも見返せるようにする

## 6. 構成

```
pekoe daemon
 ├ 状態モデル(既存)──状態遷移──▶ narrate
 ├ hook の受け口 ◀── Claude Code hooks(read 用。MessageDisplay / Stop / UserPromptSubmit)
 ├ voice policy … セッションごとのモードを決める
 ├ 整形 … 読む範囲の判定、文への分割、定型文の組み立て
 ├ 発話キュー … 直列化、優先度、鮮度の確認、まとめ、中断
 └ 再生 … Mac のスピーカー(afplay)
          │
          ▼
 speech backend(外部の実行ファイル)
   say(同梱)/ voicevox / その他
```

### 6.1 hook とセッションの結びつけ

hook が要るのは read だけ(narrate は §4.1 のとおり状態遷移から)。

- **セッションの特定**: pekoe はセッションを起動するとき、環境変数 `PEKOE_SESSION_ID` を渡す。hook スクリプトはこの変数がなければ何もせずすぐ `exit 0` する。これにより、pekoe の外で起動した Claude Code では何も起きない
- **hook の入れ方**(調査して決める。未決事項):
  - 案 A: セッション起動時に、pekoe が hook の設定を Claude Code に渡す(`claude --settings` 相当の方法が使えるか確認する)。ユーザーの設定ファイルを書き換えずに済むので、使えるならこちらを採る
  - 案 B: `pekoe voice on` のときに `~/.claude/settings.json` へ追記し、`pekoe voice off` で取り除く。既存の設定を壊さないよう、pekoe が入れた項目だけを識別して出し入れする
  - どちらの場合も、対象リポジトリの中には何も置かない
- 状態検知ですでに hook を使っている場合は、同じ受け口に相乗りする

### 6.2 `MessageDisplay` の注意と事前検証

Claude Code は、この hook が返るまで画面表示を止める。そのため hook スクリプトは次を守る。

- `PEKOE_SESSION_ID` がない、または daemon のソケットがなければ、何もせずすぐ `exit 0` する
- Unix ソケットに投げるだけにし、返事は待たない
- 何も出力しない(出力すると表示の差し替えとして扱われる)

新しいイベントなので、**P1 の中で次を検証する**(半日程度)。結果が悪ければ、read は `Stop` の `last_assistant_message` 方式で作る。

1. pekoe の pty の中で動く Claude Code でも、期待どおりに発火するか
2. バッチごとにプロセスが起動しても、表示がもたつかないか(体感と、hook 1 回あたりの所要時間)
3. 必要な Claude Code の最低バージョン

### 6.3 voice policy

セッションのモードは、次の順で決める(上にあるものが優先)。

1. 全体ミュート
2. ユーザーがセッションに明示的に指定したモード
3. フォーカス中のセッションは read(設定で narrate にもできる)
4. それ以外のセッションは narrate

### 6.4 発話キュー

- **直列**: 喋るのは同時に 1 つだけ
- **優先度**: narrate を read より優先する。read の途中に narrate が来たら、今の文を最後まで読んでから narrate を挟み、read に戻る(文の途中では切らない)
- **鮮度**: narrate の発話は、再生する直前にそのセッションの状態を確認する。すでに別の状態に変わっていたら捨てる(例: 確認待ちの通知が、順番待ちの間に解消された)
- **read の積み残し**: 読み上げは表示より必ず遅い。次の決まりで溜まりすぎを防ぐ
  - 新しいターンが始まったら、前のターンの残りを捨てる
  - 1 メッセージあたり読むのは `max_sentences` まで
- **まとめ**: キューに同じ種類の narrate が複数あれば、1 つの発話にまとめる
- **中断**: ミュート、ユーザーの入力、フォーカスの移動で、再生を止めてキューを空にする(フォーカス移動で消すのは read の分だけ)

### 6.5 再生

- `afplay` で再生する。中断するときはプロセスを止める
- 再生している間に次の文を合成しておき、文と文の間が空かないようにする
- 再生部分は後から差し替えられるよう、1 か所にまとめておく(Web UI 対応を後で足す場合に備える)

## 7. speech backend の約束事(v1)

pekoe は文字を渡して音声ファイルを受け取るだけにする。再生・中断・どこで鳴らすかは pekoe が持つ。backend は合成だけを担当する。

### 7.1 見つけ方

git のサブコマンドと同じく、PATH にある `pekoe-voice-<名前>` を backend とみなす。

```toml
[voice]
backend = "voicevox"   # → pekoe-voice-voicevox を呼ぶ
fallback = "say"       # backend の check が失敗したらこちらを使う
```

### 7.2 コマンド

| コマンド | 入力 | 出力 |
|---|---|---|
| `synth --voice <名前> --lang <ja\|en> --out <パス>` | 文字(標準入力、UTF-8) | WAV ファイルを `--out` に書く。成功なら exit 0 |
| `check` | なし | 使えれば exit 0、使えなければ 0 以外 |
| `voices` | なし | 使える声の一覧(JSON、標準出力) |
| `version` | なし | 対応している約束事のバージョン(`1`)を標準出力に書く |

- `--voice` には pekoe 側の論理的な名前(`tapi`、`reader`)を渡す。それを実際のどの声に割り当てるかは backend の設定で決める。割り当ては言語ごとに持てるようにする
- 出力は WAV に統一する(backend ごとの違いを pekoe 側で吸収しなくて済むように)
- 失敗したときは 0 以外で終了し、理由を標準エラーに 1 行で書く。pekoe はそれをログに残す
- pekoe は `synth` を同時に複数呼ぶことがある(先読みのため、最大 2 つ)。backend は並行して呼ばれても壊れないこと
- タイムアウト: pekoe は `synth` を 3 秒で打ち切り、その発話は捨てる
- `voices` の出力の形:

```json
[
  { "name": "tapi",   "lang": "ja", "label": "(backend 側の声の名前)" },
  { "name": "reader", "lang": "ja", "label": "..." }
]
```

### 7.3 同梱の backend: `pekoe-voice-say`

- macOS の `say` を使う。依存がなく、オフラインで動く
- `say -v <声> --file-format=WAVE --data-format=LEI16@24000 -o <out>`
- 声の既定の割り当ては言語ごとに持つ(例: ja は Kyoko、en はシステムの既定の声)

## 8. 外部 backend: `pekoe-voice-voicevox`

pekoe 本体とは別に配布する。日本語専用。

- VOICEVOX エンジン(`localhost:50021`)に対して、`/audio_query` → `/synthesis` の順に呼んで合成する。エンジンは VOICEVOX アプリか Docker で用意する
- **キャッシュ**: 文・声・パラメータのハッシュをキーに WAV を保存する。narrate の定型文は、起動時にまとめて合成しておく
- **ユーザー辞書**: `pekoe`→ペコー、`tapi`→タピ、`worktree`→ワークツリー などを `/user_dict_word` で登録する。辞書の中身は設定ファイルに出す
- **調整**: `speedScale` は 1.2〜1.4 程度。`prePhonemeLength` / `postPhonemeLength` を短くして、文と文の間の無音を詰める
- **規約**: VOICEVOX の声はキャラクターごとに利用規約がある。音声を公開する場合(LP のデモ動画など)は、規約に従ってクレジットを表記する

## 9. 設定

```toml
[voice]
enabled = false            # 既定はオフ。`pekoe voice on` で有効にする
lang = "en"                # 既定の文言と声の言語("en" / "ja")
backend = "say"
fallback = "say"
focus_mode = "read"        # フォーカス中のセッションのモード
background_mode = "narrate"

[voice.read]
max_sentences = 6
skip = ["code", "table", "url", "path"]

[voice.phrases]            # 文言の上書き(省略すれば lang に応じた既定の文言)。{name} にセッションの呼び名が入る
wait  = "{name}、確認待ちだよ"
done  = "{name}、終わったよ"
error = "{name}でエラーが出たみたい"
```

時間帯でのミュート(`quiet_hours`)は P4 で追加する。

CLI:

- `pekoe voice on|off`
- `pekoe voice mute [--for 30m]`
- `pekoe voice test "テキスト"`
- `pekoe voice backends`(見つかった backend と check の結果を一覧する)

## 10. セキュリティと配布

- 既定はオフ。有効にしない限り、何も鳴らず、外部コマンドも呼ばず、hook も入れない
- マイクは使わない
- 同梱の backend(`say`)はローカルで完結し、外部に通信しない
- 外部の TTS API を使う backend を入れると、本文(コード片を含みうる)が社外に送られる。ドキュメントに明記する。業務利用の申請書にも「ローカルの backend だけを使う運用ができる」と書けるようにしておく
- OSS(MIT)として、backend を作るための仕様(§7)を README か docs に載せる

## 11. 段階的な進め方

すべて Mac 上で動かす前提。

| 段階 | 内容 | 終わりの条件 |
|---|---|---|
| **P1** | narrate(状態遷移から)+ `say` backend + 再生。発話キュー、ミュート、CLI。あわせて `MessageDisplay` の事前検証(§6.2)と hook の入れ方の調査(§6.1) | 確認待ち・完了・エラーを、セッション名付きで、状態が変わってから 1 秒以内に喋る。検証と調査の結果が企画書に反映されている |
| **P2** | backend の約束事を公開し、`pekoe-voice-voicevox` を作る。キャッシュとフォールバック | VOICEVOX の tapi の声で narrate が動く。エンジンを止めると `say` に切り替わる |
| **P3** | read。整形、中断、フォーカス連動(方式は P1 の検証結果で決める) | フォーカス中のセッションの本文を、コードを飛ばして読む。入力すると止まる |
| **P4**(任意) | 長文の要約、時間帯ミュート、通知のまとめの高度化 | — |

## 12. 試用の判定

P1 を 1 週間、普段の開発で使ってから、続けるかどうかを決める。

- **続ける**: 1 週間、voice をオンのまま使い続けられた。確認待ちに気づくのが早くなった実感がある
- **見直す**: 途中でオフにした、またはミュートを頻繁に使った。その場合は、どの発話がうるさかったかを発話ログから拾い、喋る条件を絞る
- P2 以降に進むのは、P1 が「続ける」になってから
