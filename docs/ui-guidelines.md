# TUIデザイン原則 — 配色・レイアウト・実装

Nov 7, 2026 · @Yuki Sakamoto

## 目的と適用範囲

自作TUIアプリの全画面（パネル、モーダル、ボトムバー）に対して、配色・ペイン構成・キー操作の一貫性を保つための基準。見た目の方向性は「高彩度で nerdy、ただし色彩理論に基づいて整っている」、操作の方向性は lazygit に倣う。

判断に迷ったら次の3つに戻る。

1. 色が付いていたら必ず意味がある（装飾のための色は存在しない）
2. 派手さは面積ではなく彩度で出す（ネオンは画面の10%以下）
3. フォーカスは常に1つ、キーヒントは今のパネルの分だけ
4. 凝ったグラフィカル表現（アイコン・powerline・置字グラフィック）は枠に置き、内容のテキストは素のまま

## 配色の原理

「ドギツいのに整っている」は、色相の選び方ではなく明度とクロマを揃えることで作る。設計はすべて OKLCH（知覹的に均一な色空間）で行い、HSL/HSV は使わない。

### 1. アクセントは明度とクロマを揃える

5つのアクセント色は L＝0.78（黄のみ 0.84）、C＝0.14〜0.20 に固定する。明度が同じなら、彩度が高くてもどれか1色だけが飛び出して「うるさい」状態にならない。黄だけ明度を上げるのは、sRGB では L0.78 の黄がマスタード色に沈むため（黄の最大クロマは高明度側にある）。

### 2. 色相は構造で選ぶ：三角配色＋補色ペア

- マゼンタ（h340）・シアン（h215）・イエロー（h95）＝CMY の三角配色。UI の操作系（フォーカス・キー・警告）に割り当てる。
- 赤（h22）・緑（h145）＝補色ペア。データの状態（diff の A/D、成否）に割り当てる。
- 合計は5色相＋無彩色。これ以上色相を足さない。

「印刷インクの三原色をそのまま使う」理屈っぽさが、nerdy な印象の根拠になる。

### 3. 背景は「冷たくて低クロマ」、真っ黒にしない

背景は L0.20、C0.025、h285（青紫）。ネオンが夜景のように映えるのは、地が冷たく低彩度だから。#000000 はコントラストが過剰になってハレーションし、安っぽく見える。テキストも純白 #ffffff ではなく、背景と同じ色相にわずかに寄せた L0.91 を使う。

### 4. 面積の規律（60-30-10）

背景と本文（無彩色）が画面の90%を占める。ネオンはフォーカス枠・選択行・キー文字・状態記号に限り、10%以下。ネオン色で文章を書かない。派手さは面積ではなく彩度で出す。唯一の例外は powerline ステータスラインのモードセグメント（primary 塗り、1つだけ）。

### 5. 派生色は同一色相で L と C を落とす

選択行の背景 #441e39 はマゼンタを L0.30、C0.07 に落としたもの。色相を変えずに「主役の影」を作れ、色族が増えない。新しい色が欲しくなったら、まず既存役割の派生で済ませる。

例外として、フォーカス枠のグラデーション終点 primary\_end（#9bb7f2）だけは色相を動かした派生を置く。L は primary と同じ 0.78 に揃え、C は 0.090 に下げる（Pantone Serenity #92a8d1 の h263・C0.065 に寄せた、くすんだペリウィンクル）。これは新しい役割ではなく「primary の行き先」で、単独では使わない。色相 265 は secondary（h215）から 50° 離れており、キー文字のシアンと取り違えない。

### 6. コントラストの下限

対背景で、本文 7:1 以上、アクセントと dim テキスト 4.5:1 以上（WCAG AA/AAA）。現行パレットは本文 13.9:1、アクセント 6.8〜11.2:1、dim 5.0:1 ですべて満たす。パレットを変えるときはこの値を再計算する。

## カラートークン

コードから参照するのは役割名だけ。hex はテーマファイルにのみ書く。コントラストは対 bg（#151421）、select のみその上に乗る text との値。

| 役割 | hex | OKLCH (L / C / h) | コントラスト | ANSI | 用途 |
| --- | --- | --- | --- | --- | --- |
| bg | #151421 | 0.20 / 0.025 / 285 | — | 端末背景 | 画面背景 |
| surface | #1e1d2c | 0.24 / 0.028 / 285 | 1.1:1 | 端末背景 | フォーカス中パネルの背景（任意） |
| border | #3b3b4d | 0.36 / 0.030 / 285 | 1.7:1 | 8 bright black | 非フォーカスの枠線・区切り |
| dim | #848495 | 0.62 / 0.025 / 285 | 5.0:1 | 8 bright black | 補助テキスト、ヒントの動作名、idle |
| text | #e0e0eb | 0.91 / 0.015 / 285 | 13.9:1 | 端末前景 | 本文 |
| primary | #ff87da | 0.78 / 0.174 / 340 | 8.4:1 | 5 magenta | フォーカス枠・フォーカスタイトル・モーダル枠 |
| primary\_end | #9bb7f2 | 0.78 / 0.090 / 265 | 9.1:1 | —（primary 単色） | primary の派生。フォーカス枠・モーダル枠のグラデーション終点のみ |
| secondary | #11cded | 0.78 / 0.136 / 215 | 9.5:1 | 6 cyan | キー文字・リンク・カレントマーカー・プロンプト |
| warn | #edc812 | 0.84 / 0.170 / 95 | 11.2:1 | 3 yellow | 確認待ち・Modified・警告 |
| ok | #51d75e | 0.78 / 0.200 / 145 | 9.7:1 | 2 green | 稼働中・Added・成功 |
| err | #ff7172 | 0.72 / 0.174 / 22 | 6.8:1 | 1 red | 失敗・Deleted・破壊的操作の確認 |
| select | #441e39 | 0.30 / 0.070 / 340 | text 10.8:1 | reverse | 選択行の背景 |

補足：

- C は sRGB ガマットに收めた後の実効値。マゼンタと赤は設計値 0.21〜0.22 からクリップされている。
- ANSI 列は truecolor が使えないとき、またはユーザーが端末のテーマに合わせたいときのフォールバック。
- 役割を足すときは「既存役割の L/C 派生で済まないか」を先に問う。色相の追加は原則としてしない。
- primary\_end は「色相の追加」に数えない。役割を持たず、枠線上で primary から連続的に流れる途中の色としてしか現れないため、画面上で独立した意味を担わない（原則「色が付いていたら必ず意味がある」の意味は「フォーカス」のまま）。単独の文字や記号に使うことは禁止。
- グラデーションは OKLCH で補間する（色相は短い弧: 340 → 302 の紫 → 265）。sRGB 補間だと中間がくすむため。全段で L0.78 を保ち、中間はすべて sRGB ガマット内、対 bg コントラストは 8.4〜9.1:1。

## レイアウトとフォーカス

左に番号付きの文脈パネルを縦積み、右にメインパネル、最下行にキーヒント。この固定グリッドを全画面で崩さない。

```text
+-[1] Sessions 2/4 -----+  +-[4] Agent login-ui ----------------+
| * auth-fix      run   |  | > add validation to login form      |
|#* login-ui      wait  |  | 3 files, 42 lines                   |
| o perf          idle  |  | + if (!email) {                     |
| v docs          done  |  | +   setError(...)                   |
+-----------------------+  | - submit()                          |
+-[2] Worktrees --------+  |                                     |
| main                  |  |                                     |
| feat/login *          |  |                                     |
+-----------------------+  |                                     |
+-[3] Changes 3 --------+  |                                     |
| A login.tsx           |  |                                     |
| M auth.ts             |  | ? apply? y/n                        |
+-----------------------+  +-------------------------------------+
 j/k move  enter open  n new  d del  ? help
```

【グリッド】

- 左列 40%／右列 60%。左列は3〜5パネル。パネルには 1〜5 の番号を振り、数字キーで直接フォーカスできる。
- フォーカス中の左パネルは広がり、他はタイトル＋1〜2行に縮む（アコーディオン）。
- 端末幅が 100 列未満のときは左列をタブ化して1枚にする。メインパネルは消さない。

【フォーカス】

- フォーカスは常に1つ。表現は「枠線とタイトルを primary にする」だけ。パネル背景は塗らない（surface への切替は任意、差は L+0.04 まで）。
- truecolor ではフォーカス枠を primary → primary\_end の静的グラデーションで描く。方向は左上 → 右下の対角線（上辺と左辺から始まり、右辺と下辺へ流れる）。枠を一周させると左上でピンクと青がぶつかる継ぎ目ができるため、対角にした。端末のセルは縦が横の約2倍なので、行の進みを2セル分として数える。アニメーションはしない。
- タイトル文字はグラデーションにせず primary 単色（太字）のまま。読みやすさを優先し、枠の始点（左上）がちょうど primary なのでタイトルと枠が自然につながる。
- ansi / none モード、またはテーマファイルで primary だけを上書きしたときは、従来どおり primary 単色の枠に戻る。
- 非フォーカスは枠線 border、タイトル dim。
- モーダルが開いている間はモーダルが唯一のフォーカス。背後のパネルは枠線を border に落とす。

【タイトル行】

- 形式は `[n] 名前 位置 状態` を1行で。例：`[1] Sessions 2/4`、`[3] Changes 3`、`[4] Agent login-ui`。
- フィルタやソートがかかっているときは末尾に追記する（`[3] Changes 3 filter:ts`）。状態をタイトル以外の場所に散らさない。

【選択行】

- 選択行は select で背景を塗り、パネルの内幅いっぱいに延びる。カーソル記号（> など）は置かない。
- 非フォーカスパネルの選択行も残す（パネル間の文脈が追える）が、ansi モードでは reverse video で代用する。

【フッター行】

- パネル最下行に dim の集計行を1行置ける（`1 waiting · oldest 3m   1 to review`）。状態アイコンは状態色のまま、文字は dim。本文色は使わない。
- フッターにキーヒントは置かない（ボトムバーの仕事）。
- Changes パネルのフッターは衝突予報の集計（`⚠ feat-b conflict   ⚠ feat-c overlap`）。各ファイル行の末尾にも、同じファイルを触っている相手を `⚠ slug` で添える（パスが先に縮む）。

【ペイン内カード】

- メインペインに外から届くもの（ブラウザの要素ピック、エージェントからの質問、通知）は、ペイン内の枠付きカードで示す。枠線は border 色、タイトル行の先頭アイコンだけ secondary。primary の枠はフォーカスにしか使わないので、カードには使わない。
- カード最下行にそのカード専用の `key action` を書く。ボトムバーは変えない。
- カードは同時に1枚。2枚目以降は Picks パネルの行として待たせ、未送信は secondary の ● で示す。
- 優先順位は ピック > エラー。ピックは人が自分で送ったもの、エラーは boba が見つけて提案するものなので、ピックのカードがある間エラーのカードは出さない（Picks パネルの行で待つ）。
- カードはフォーカスを奪わない。キーが効くのはメインパネルにフォーカスがあり、入力中でないときだけ（それ以外のときカードの最下行は `4 focus card`）。エージェントへの送信は人がキーを押したときだけ。
- エラーカード：タイトル行は「発生源のアイコン（dev はターミナル、ブラウザは Browser）＋ fail アイコン（err）＋ error ＋ dim の発生源・形式・経過時間」、続けてメッセージ1行、`at file:line · ×回数`、最下行に `s send  i ignore  ↵ detail`。カードが i と ↵ を使う間、エージェントへの入力は `a`。未対応のエラーがあるセッションは Sessions の行に err 色の `err`（2件以上は `2 err`）を付ける。
- 画像やスクリーンショットの添付は、破線枠のプレースホルダにサイズと形式を書いて示す（`clip 320×96 · png`）。インライン画像表示（Kitty graphics など）は対応端末でのみ、プレースホルダを置き換える形で。

## キーヒントと操作体系

ボトムバーは「今フォーカスしているパネルでいま押す意味があるキー」だけを表示する。全部は `?` に退避させる。

【ボトムバー】

- 最大6個。形式は `key action`、key は secondary、action は dim、区切りはスペース2つ。
- action は英小文字の動詞1語（move / open / new / del / help）。名詞や文にしない。
- パネルを移ると即座に入れ替わる。グローバルキー（数字、Tab、q）はバーに載せない。
- 幅が足りないときは後ろから落とす。最後に残るのは `?` 。

【全一覧 `?`】

- 中央モーダル。上半分に現在パネルのキーをすべて、下半分にグローバルキー。
- 一覧の行を選んで Enter で実行できる（lazygit のメニューと同じ）。読むだけのヘルプにしない。

【グローバルキー（固定、パネルで上書き禁止）】

| キー | 動作 |
| --- | --- |
| 1〜5 | パネルを直接フォーカス |
| Tab / Shift+Tab | 次・前のパネル |
| h j k l / 矢印 | 移動 |
| Enter | 掘る（開く・決定） |
| Esc | 戻る（閉じる・取消） |
| \[ \] | パネル内のサブタブ切替 |
| ? | キー一覧 |
| : | コマンド入力 |
| q | 終了（稼働中があれば確認） |

【パネル固有キー】

- 同じ意味にはどのパネルでも同じキーを使う：n 新規、d 削除、r リネーム、Space 選択トグル、/ フィルタ。
- 破壊的操作（削除、中断、稼働中セッションの終了）は必ず確認モーダルを通す。

【モーダル】

- 中央配置。枠線とタイトルはパネルと同じ言語（通常は primary → primary\_end のグラデーション、破壊的操作の確認は err 単色）。
- 確認は `y/n` か Enter/Esc。選択肢はボトムバーと同じ `key action` 形式でモーダル内最下行に書く。
- 判断材料がある確認（land の衝突予報など）は、問いの直上に1件1行で添える（最大3行、超えた分は `+N more`）。行頭は状態アイコン（状態色）、相手の名前は text、説明は dim。
- 背後を暗くする効果は使わない（端末によって見え方が安定しない）。背後の枠線を border に落とすだけで十分。
- 実行対象（コマンド、ファイルパス、ブランチ名）は全幅1行で bg 色に沈めて見せる。モーダルの surface に対して1段凹むので、何が実行されるかが読む前に分かる。その行に色文字は置かない。
- 進行中の処理はステップのリスト（✓ / スピナー / ○）で縦に並べ、時間のかかる段だけゲージを付ける。全体の進捗バーは置かない。

## 状態の表現

色は状態とデータの意味にだけ使い、常に記号とペアにする。記号だけでも状態が読めることが、色覚多样性と ansi/none モードへの保険になる。

| 状態 | 記号 | 色 | 例 |
| --- | --- | --- | --- |
| 稼働中 | ● | ok | エージェントが実行中 |
| 確認待ち | ● | warn | 人の判断を待っている |
| 待機 | ○ | dim | 起動済みで何もしていない |
| 作成中 | ◌（スピナー） | dim | worktree 作成からセッション起動までの間。まだエージェントはいないので ok にしない |
| 完了 | ✓ | secondary | 結果のレビュー待ち |
| 失敗 | ✗ | err | エラー終了 |
| 承認済み | ✓ | ok | レビューで承認したハンク・ファイル |
| 現在位置 | ▶ | primary | レビュー中のハンクなど、選択行の塗りと並立で「今ここ」を示す |
| 未送信 | ● | secondary | 届いたが未送信のピック、未送信のコメント |
| 送信済み | ✓ | dim | 送ったピック・コメント |
| 追加 | A | ok | diff の新規ファイル・+ 行 |
| 変更 | M | warn | diff の変更ファイル |
| 削除 | D | err | diff の削除ファイル・- 行 |
| カレント | \* | secondary | 今いる worktree ・ブランチ |
| 重なり | ⚠ | warn | 他のセッションも同じファイルを触っている（自動マージ可）。一覧では `⚠2` のように相手の数と並べる |
| 衝突 | ⚠ | err | コミット済みの内容が他のセッションと衝突する（git merge-tree）。詳細では状態語 conflict / overlap を添える |

ルール：

- 「確認待ち」は warn に固定する。エージェント環境で最も気づいてほしい状態がこれなので、画面内で黄が別の意味で多用されないようにする。
- 表の記号は icons = unicode のもの。nerd / ascii での対応は「アイコンとグラフィカル表現」の語彙表に従う。
- unicode 段階で稼働中と確認待ちが同じ記号 ● なのは意図的。「今生きている」を記号で、「自分か相手か」を色で分ける。nerd 段階では pause\_circle、ascii では \* と ! で区別され、none モードでも状態語（run / wait）が必ず付くので別がつく。
- 同じ色は同じ種類の意味にだけ使う。warn が「待ち」と「変更」に跨っているのはどちらも「注意を向ける対象」だから。ok を「成功」と「稼働中」に使うのも同じ理由。
- 状態の文字列は英小文字の短語（run / wait / idle / done / fail）。記号・色・語の3つが常に揃って出る。
- 強調は色で行い、太字はフォーカス中のタイトルとキー文字にだけ使う。点滅・下線・イタリックは使わない。

## アイコンとグラフィカル表現

Nerd Font のアイコンと置字グラフィック（powerline、ブロック要素、Braille）は nerdy なかっこよさの中核として積極的に使う。ただし使う場所は「枠（chrome）」に限り、エージェントの出力や diff 本文は素のテキストのままにする。凝った枠があるから内容が引き立つ。

### アイコンの語彙

| 警告（モーダル）・衝突予報 | nf-fa-exclamation\_triangle | F071 | ⚠ | ! | warn / err |
| PR ビュー / open の PR | nf-dev-git\_pull\_request | E726 | ⇄ | なし | タイトル色（状態行では ok） |
| PR の CI 実行中・待ち | nf-fa-clock\_o | F017 | … | ~ | dim |
| PR の CI 全成功 | （check と同じ） | — | ✓ | v | ok |
| PR の CI 失敗 | （fail と同じ） | — | ✗ | x | err |
| PR の changes requested | nf-fa-exclamation\_circle | F06A | ! | ! | warn |
| PR merged | nf-dev-git\_merge | E727 | ↣ | m | secondary |
| PR closed | nf-fa-ban | F05E | - | - | dim |
| セグメント区切り | powerline hard / rounded caps | E0B0, E0B2 / E0B6, E0B4 | │ | \| | 塗り色 |

セッション一覧の `#42` タグの後ろには PR の状態アイコンを 1 つだけ置く。優先順は merged → closed → CI 失敗 → changes requested → CI 実行中 → CI 全成功。位置が固定（PR 番号の直後）なので状態語は省くが、6 つの状態は全アイコンセットで別の記号にする（テストで保証）。CI 実行中にスピナーは使わない（動きは run 状態のアイコン位置だけ）。

diff の A / M / D は全モードで文字のまま（git の慣習を崩さない）。truecolor では行頭に ▎ のガターマークを ok / err で添える。

### アイコンのルール

- アイコンは1セル＋スペース1つ。Nerd Font Mono を前提に設計し、Ghostty で幅がずれるグリフは語彙から外す。
- 色は「それが指すものの役割色」。パネルタイトルのアイコンはタイトルと同色（フォーカス中 primary、それ以外 dim）。
- アイコン単独で意味を持たせない。状態語か、位置が固定された列と必ずペアにする（「状態の表現」と同じ原則）。
- 1行に置くアイコンは、実体アイコン1つ＋状態アイコン1つまで。
- キーヒントはテキストのまま。キーをアイコンに置き換えない。
- `icons = nerd | unicode | ascii` の3段階を設定で持つ。Nerd Font の有無は端末から検出できないので、デフォルト nerd、初回起動時にサンプルを見せて選ばせる。

### powerline ステータスライン

ボトムバーは powerline 形式にする。左にセグメント、右にキーヒント。

```text
[MODE] SESSIONS [/]  feat/login  |  2 run  1 wait                   j/k move  enter open  ? help
 ^ primary 塗り、文字は bg          ^ select 塗り、文字は text/dim     ^ 塗りなし、key action 形式
```

- セグメントは丸キャップ（E0B6 / E0B4）のピル形。角型（E0B0 / E0B2）と混ぜない。
- ネオンの塗りはモードセグメント1つだけ（primary 塗り＋ bg 色の文字。コントラスト 8.4:1）。これが「面積の規律」の唯一の例外。他のセグメントは select か surface の塗り。
- 左セグメントは最大4つ（モード・ブランチ・セッション集計・任意）。キーヒントは塗りなしで、「キーヒントと操作体系」の規則をそのまま適用。
- ansi モードではセグメントの塗りをやめて `│` 区切りのテキストに落とす。

### 置字グラフィック

| 表現 | 使う文字 | 用途 | 色 |
| --- | --- | --- | --- |
| スピナー | ⠇⠙⠹⠸⠼⠴⠦⠧⠇⠏（10コマ、80ms） | run 状態のアイコン位置 | ok |
| スパークライン | ▁▂▃▄▅▆▇█ | セッションごとの直近の活動量、トークン消費 | dim（最新点のみ secondary） |
| ゲージ | ━（値）＋ ─（残り） | 進捗、コンテキスト使用率 | 値は ok、80%超で warn、残りは border |
| ツリー | ├─ └─ │ | worktree やファイルの階層 | border |
| スクロールバー | │（トラック）＋ ┃（サム） | メインパネル右端 | border / dim |
| ガターマーク | ▎ | diff の追加・削除行 | ok / err |
| 枠線 | ╭ ╮ ╰ ╯ ─ │ | 全パネルとモーダル | primary → primary\_end（フォーカス・モーダル）/ border / err |
| 紙吹雪 | nerd: nf-fa-star（F005）・nf-fa-star\_o（F006）・✦ ⁺ / unicode: ✦ ✧ ⋆ ⁺ / ascii: * + ' . | PR がマージされたときの tapi のトーストの枠線上だけ（`docs/mascot.md`「PR と CI への反応」） | secondary |

- 動きはスピナーだけ。点滅やマーキーは使わない。フォーカス枠のグラデーションも静止している。`animate = false` でスピナーも静止アイコンになる。例外は tapi（`docs/mascot.md` のタイミング規則に従う。紙吹雪の瞬きもここ）で、`animate = false` なら tapi も止まり、紙吹雪は出さない。
- 空のメインパネルには dim の ASCII アートロゴ（6行以内）を置いてよい。アクセントは primary の文字1つまで。
- スパークラインやゲージは数値とペアで置く（`▂▅▇█ 42%`）。グラフィックだけで数値を読ませない。

## 実装ルール

テーマは「役割 → 色」の対応表であり、コードは役割しか知らない。これを守るとユーザーが自分の端末に合わせて rice できる。

【役割ベースのテーマ】

- 描画コードからの参照は `theme.primary` のように役割名のみ。hex リテラルを書いたらレビューで差し戻す。
- デフォルトテーマはバイナリに同梱。ユーザーテーマは設定ディレクトリ（対象リポジトリの外）に置き、役割単位で上書きできる。

```toml
[theme]
mode      = "auto"      # truecolor | ansi | none | auto

[theme.colors]
bg        = "#151421"
surface   = "#1e1d2c"
border    = "#3b3b4d"
dim       = "#848495"
text      = "#e0e0eb"
primary   = "#ff87da"
primary_end = "#9bb7f2" # フォーカス枠グラデーションの終点。省略時、primary を上書きしていれば単色。primary と同じ値で単色にできる
secondary = "#11cded"
warn      = "#edc812"
ok        = "#51d75e"
err       = "#ff7172"
select    = "#441e39"

[theme.ansi]            # mode = ansi のときの対応
border    = 8
dim       = 8
primary   = 5
secondary = 6
warn      = 3
ok        = 2
err       = 1
```

【カラーモード】

- `auto` は `NO_COLOR` があれば none、`COLORTERM=truecolor|24bit` なら truecolor、それ以外は ansi。
- ansi モードでは bg / surface / select を塗らない。端末の背景を尊重し、選択行は reverse video。
- none モードでも記号と状態語で全状態が読めることをテストで保証する。

【パレットの変更手順】

1. OKLCH で値を決める（アクセントは L を揃える）。
2. sRGB ガマットに入るまで C を落とす（L と h は動かさない）。
3. 対 bg コントラストを計算し、「配色の原理 6」の下限を満たすか確認する。
4. カラートークン表を更新する。

【その他】

- ダークのみ対応。ライト背景の端末は ansi モードで受ける。
- 枠線は丸角の box-drawing（╭ ╮ ╰ ╯）を標準とし、フォントが持たないときは角型にフォールバック。アイコンと置字グラフィックは「アイコンとグラフィカル表現」の節に従う。

## 禁止事項とチェックリスト

【やらないこと】

- ネオン色（primary / secondary / warn / ok / err）で2行以上の文章を書かない
- 装飾目的の色を置かない（セパレータの色分け、タイトルごとの色変えなど）
- 1画面にフォーカス表現を2つ作らない
- 色相を6つ以上にしない。新色は既存役割の L/C 派生で作る
- \#000000 の背景、#ffffff のテキストを使わない
- 記号を伴わない色だけの状態表示をしない
- ボトムバーに7個以上のキーを載せない。グローバルキーを載せない
- 点滅・下線・イタリック・タイトル以外の太字を使わない
- 背後を暗くするモーダル効果を使わない
- コードに hex を直書きしない
- 語彙表にないアイコンを使わない。1行に実体1＋状態1を超えるアイコンを置かない
- エージェント出力や diff 本文にアイコン・powerline・装飾を入れない
- ネオンの塗りは powerline のモードセグメント1つまで

【新しい画面・パネルを作るときのチェック】

- [ ] 色の付いた要素すべてに、カラートークン表の「用途」に合う意味がある
- [ ] ネオンの面積が画面の10%以下（モードセグメント以外にネオンの塗りがない）
- [ ] フォーカスは1つで、枠線＋タイトルだけで示している（グラデーションはフォーカス枠とモーダル枠だけ）
- [ ] タイトル行が `[n] アイコン 名前 位置 状態` の形式
- [ ] 選択行は select の背景塗りで、カーソル記号がない
- [ ] ボトムバーがこのパネルのキーだけ、6個以内、`key action` 形式
- [ ] パネル固有キーが他パネルの同じ意味のキーと一致している
- [ ] すべての状態に記号・色・状態語の3つが揃っている
- [ ] アイコンは語彙表のものだけで、同じ概念に同じアイコンを使っている
- [ ] グラフィカル表現は枠に限られ、内容テキストは素のまま
- [ ] 破壊的操作に確認モーダルがあり、枠線が err
- [ ] icons = ascii でも状態と構造が読める
- [ ] ansi モードと none モードで表示して破綻しない
- [ ] 端末幅 100 列未満でレイアウトが崩れない
- [ ] 新しい色を足していない（足したならトークン表とコントラスト値を更新済み）
