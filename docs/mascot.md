# pekoe マスコット設計書

Nov 7, 2026 · @Yuki Sakamoto

## 概要とコンセプト

pekoeのマスコットは**タピオカの粒**。粒の名前は **tapi**（たぴちゃん。コード上の識別子も `tapi`）。描くのは粒だけで、カップ・ストロー・ミルクティーの背景は描かない。

pekoe と tapi の関係は「家」と「そこにいる相棒」。pekoe はコーディングエージェントたちが暮らす家そのもので、worktree・セッション・レビューといった部屋を用意する側。tapi はその家に住みついている小さな相棒で、家の中の様子(誰が働いていて、誰があなたを待っているか)を顔と1行の声で伝える。

顔を出すのは常時1か所（最下行のステータスバー）だけ。それ以外の場所では外部の statusline の1セルの点として、または pekoe が話す1行の文として現れる。マスコットは飾りではなく状態表示の器であり、情報を持たないときは出さない。

設計原則：

1. **顔は1か所** — 画面上に顔が同時に2つ出ない
2. **他は点か声** — セッション一覧の行頭は状態アイコン（nerd / unicode / ascii のアイコンセット）、pekoe 自身がユーザーに尋ねるときは1行の顔を文頭に置く
3. **意味があるときだけ動く** — アニメーションは「進行中」「確認待ち」など状態を伝えるときだけ。Ghostty が非フォーカスなら全停止
4. **体色はテーマトークン** — 配色を固定せず、highlight / body / shadow / eye の4色をテーマから解決する
5. **フォントに頼らない** — 輪郭はブロック文字（Ghostty が内蔵描画する）で作り、表情だけをグリフで乗せる

仕様は検証用のモック（配色・形・状態を切り替えられ、Ghostty で貼れる printf とスプライト JSON を出力できるもの。公開していない）で詰めた。

## キャラクター仕様

標準形は六分ブロック（sextant, U+1FB00–U+1FB3B）で輪郭を作る **round**。5桁×3行で、セル 10×20px なら 50×47px の横長の円になる（横幅 30→40→50→40→30px の段）。四分ブロックだけの **block** は角が丸まらず長方形になるので、六分ブロックが使えない環境のフォールバック扱い。

```
🬞🬹🬹🬹🬏      ▐● ●▌      ●
█● ●█
🬁🬎🬎🬎🬀
3行(5桁)    1行         1セル
```

| サイズ | 寸法 | 用途 |
| --- | --- | --- |
| 1セル | 1×1 | Neovim statusline、tmux など外部。色だけで状態を出す |
| 1行 | 5×1 | ステータスバー、pekoe 自身のプロンプト接頭辞、トースト |
| 3行 | 5×3 | 主ペインの空状態、起動スプラッシュ、`pekoe --help`（後2つは右に文字を添える） |

描き方は、輪郭セルを前景色で塗り、目の3セルだけ背景色＝body にして目のグリフを乗せる。表情は目の文字の差し替えだけで変わり、再描画はその3セルで済む。

配色は4つの役割（highlight / body / shadow / eye）をテーマトークンとして持つ。初期値はダークテーマ＝D、ライトテーマ＝E。ライティングは **glint**（上段左から2セル目だけ highlight、下段と中段の右端が shadow）。上段を丸ごと明色にするとドングリの帽子に見えるのでやらない。

| トークン | D ミルキー＋影（ダーク用） | E キャラメル（ライト用） |
| --- | --- | --- |
| highlight | #f8ecd9 | #b9825e |
| body | #e4c49a | #8a5538 |
| shadow | #c7a57c | #6e432c |
| eye | #2b201c | #f6e7cf |

状態のアクセント色（ダーク / ライト）：working #e8a85c / #c2711c、waiting #f2d06b / #b08400、done #93d39b / #3a8a3f、error #ef6f78 / #c93a46、idle はテーマの dim 色。

## 状態と表情

セッションの状態は6つ。顔は目の3文字だけで表し、体色は変えない。複数セッションを集約するときは優先度の高い状態を採る。

| 優先 | 状態 | 目 | 1セル | アクセント | 意味 |
| --- | --- | --- | --- | --- | --- |
| 1 | error | `⨯ ⨯` | `⨯` | 赤 | エージェントが異常終了、またはコマンド失敗で停止 |
| 2 | wait | `◕ ◕` | `◉` | 黄 | エージェントがユーザーの入力・許可を待っている |
| 3 | work | `● ●` | `●` | 橙 | エージェントが出力中、またはコマンド実行中 |
| 4 | done | `^ ^` | `●` | 緑 | ターンが終わり、ユーザーがまだ見ていない |
| 5 | idle | `• •` | `•` | dim | プロンプトで待機。見た後の done もここに戻る |
| 6 | sleep | `- -` | `◦` | dim | 全セッションが3分以上 idle。集約表示でのみ使う |

wait の目は `◕ ◕`（puppy）。黒目を大きくして「お願い」の顔にし、見開き（`◉ ◉`）は怖いので使わない。`◕` はフォントでは左上4分の1が欠けた円として描かれる。Ghostty で欠けが気になる場合の代替は `˙ ˙`（見上げる目）。

1セルの wait は顔ではなく状態記号なので `◉` のまま。done と work は1セルでは同じ `●` で、色だけが違う。

## 表示設計

常時表示は最下行のステータスバーだけ。そこの1行の顔が全セッションの集約状態を表し、右隣のテキストが粒の台詞として「どのセッションが何をしているか」を言う。口がない分をこのテキストで補う。

| 場所 | 形 | 出す条件 | 内容 |
| --- | --- | --- | --- |
| ステータスバー（最下行左端） | 1行 | 常時 | 集約状態の顔 ＋ 台詞。例：`▐● ●▌ 3 working` / `▐◕ ◕▌ fix-ci needs you` / `▐⨯ ⨯▌ auth-refactor failed` / `▐- -▌ all quiet` |
| 主ペイン | 3行 | 空のときだけ | セッション未選択、worktree 作成中、依存インストール中。中央に顔と短いキャプション。泡アニメはここ専用。セッション未選択と worktree 作成中だけ、キャプションの下に TIPS を 1 つ添える(README「TIPS」。`.` で次へ。入らなければ出さない) |
| pekoe 自身のプロンプト | 1行 | pekoe が尋ねるとき | `▐◕ ◕▌ delete worktree fix-ci? [y/n]` のように文頭に置く。puppy＝「pekoe が聞いている」を一貫させる |
| トースト（右下、2行） | 1行 | 見ていないセッションが wait / error になったとき | `▐◕ ◕▌ fix-ci needs you`。数秒で消える。任意キーでも消える。表示中のセッションについては出さない |
| tapi chat のタイトル | 1行 | `t` で tapi chat(docs/tapi-chat.md)を開いている間 | `▐● ●▌ [4] tapi chat · claude · thinking`。目は tapi chat のエージェントの状態(running → work、waiting → wait、idle → idle、未起動 → sleep、終了 → error)。この間ステータスバーは顔を出さず台詞だけにする(顔は1か所) |
| ステータスバーの台詞(tapi chat) | — | tapi chat を閉じている間に許可待ち・質問待ちになり、セッションの wait / error が無いとき | `▐◕ ◕▌ chat waits · t`。セッションの wait より弱い。トーストや通知は出さない |
| スプラッシュ | 3行＋文字 | 起動時 | 集約状態の顔の右に名前・バージョン・生きているセッション数。1秒かキー入力で消える |
| CLI / README | 3行＋文字 | `pekoe --help`、README の頭 | 静止画 |
| Neovim statusline / tmux | 1セル | プラグインが入っているとき | 集約状態の点。pekoed から状態を受け取る |

出さない場所：エージェントの出力ペイン（オーバーレイしない）、セッション一覧の各行、ダイアログの本文。エージェント自身の許可プロンプトはエージェントのものなので触らず、pekoe は状態を伝えるだけ。

集約のルール：ステータスバーの顔は、表示中かどうかに関係なく全セッションの最優先状態。台詞はその状態のセッション名を言い、複数なら件数（`2 need you`）。台詞は小文字、感嘆符なし、最大でもバーの半分。

## タイミングとアニメーション

アニメーションは最大でも 2.5fps（400ms）、ステータスバーでは 1fps 以下。Ghostty のウィンドウがフォーカスを失ったら全タイマーを止め、戻ったら再開する。

| 対象 | ルール |
| --- | --- |
| 瞬き | idle / work で `- -` を1フレーム。間隔は 4–6 秒でランダム |
| 泡（work） | 主ペインが空の3行表示だけ。右隣の1列で `·` → `°` → `°` → 無を 400ms 間隔で巡回 |
| 台詞の点滅（wait） | 表示3：非表示1 の比で、周期 1.6 秒。`?` を出すのは3行表示とトーストだけ |
| チラ見（wait） | 6フレームに1回 `˙ ˙` で頭上を見る。バーではやらない |
| z（sleep） | 4秒に1回、右上へ `z` → `z` → `Z` → 無 |
| done の戻し | セッションを表示したら即時、未表示でも 10 秒で idle |
| error の戻し | 表示するまで保持。時間では消えない |
| sleep へ | 全セッションが 3 分以上 idle。キー入力か pekoed のイベントで起きる |
| トースト | 5 秒で消える。任意キーでも消える。同じセッションについては再表示しない |
| スプラッシュ | 1 秒かキー入力で消える |
| wait のエスカレーション | 0 秒：顔と台詞 → 30 秒：台詞を点滅 → 2 分：OS 通知（OSC 777 または OSC 9。Ghostty 非フォーカス時のみ） |

&#91;embedded content: セッション状態の遷移 · 6状態\]

wait と work の往復が日常のループで、done と error は「ユーザーが見た」を契機に idle へ戻る。

## PR と CI への反応

セッションの PR（pekoed が 60 秒ごとに取る要約、`Session.pr_status`）が変わったとき、tapi が1回だけトーストで反応する。遊びの要素だが、どのセッションの何番の PR で何が起きたかを1行で言うので、状態の通知も兼ねる。

反応は「前に見た要約」と「今の要約」の差から作る（`mascot.PRDiff`）。同じ状態がポーリングで何度届いても反応しない。最初に見た要約（起動直後、PR が新しく付いたとき）は基準にするだけで反応しない。

| 優先 | イベント | 条件（前 → 今） | 目 | ascii | 色 | 表示 | 気持ち |
| --- | --- | --- | --- | --- | --- | --- | --- |
| 1 | merged | MERGED になった | `✦ ✦` ＋枠に散って瞬く紙吹雪 | `* *` | 緑 | 4 秒 | お祝い。PR ごとに一回きり |
| 2 | ci\_failed | 失敗 check が 0 → 1 件以上 | `╥ ╥` | `T T` | 赤 | 5 秒 | しょんぼり（error の `⨯ ⨯` とは別の顔） |
| 3 | changes\_requested | reviewDecision が CHANGES\_REQUESTED になった | `> <` | `> <` | 黄 | 5 秒 | ちょっと緊張 |
| 4 | new\_comment | 未解決スレッドが増えた、または未解決スレッドに新しいコメント | `◒ ◒` | `o.o` | 黄 | 5 秒 | 気にする（下を見て読んでいる） |
| 5 | approved | reviewDecision が APPROVED になった | `◠ ◠` | `^.^` | 緑 | 4 秒 | 照れる・うれしい |
| 6 | ci\_passed | check が全部成功の状態になった | `^ ^` | `^ ^` | 緑 | 4 秒 | 喜ぶ |
| 7 | ci\_running | 実行中が 0 → 1 件以上（失敗なし） | `◔ ◔` ↔ `◓ ◓` | `. .` ↔ `o o` | dim | 3 秒 | そわそわ見守る（800ms で目線が動く） |

CLOSED は何もしない。MERGED と同時に CI が通っても merged だけを言う。

セリフ（`tapi.json` の `reactions`。イベントごとに3つ。どれを言うかは反応の中身から決まるので、同じ反応は何度描き直しても同じ文）：

| イベント | セリフ |
| --- | --- |
| merged | `fix-ci #42 merged` / `fix-ci #42 is in, congrats` / `fix-ci #42 merged, nice work` |
| ci\_failed | `fix-ci #42 CI fell over` / `fix-ci #42 failing checks: 2` / `fix-ci #42 CI didn't make it` |
| changes\_requested | `fix-ci #42 got change requests` / `fix-ci #42 they want some fixes` / `fix-ci #42 changes requested` |
| new\_comment | `fix-ci #42 has new comments` / `fix-ci #42 unresolved: 3` / `fix-ci #42 someone said something` |
| approved | `fix-ci #42 got approved` / `fix-ci #42 approved, feels good` / `fix-ci #42 passed review` |
| ci\_passed | `fix-ci #42 CI passed` / `fix-ci #42 all green` / `fix-ci #42 every check passed` |
| ci\_running | `fix-ci #42 watching CI` / `fix-ci #42 checks are running` / `fix-ci #42 CI, fingers crossed` |

文頭は必ず `<ブランチ名> #<PR 番号>`。英語の短い口語で（直訳ではなく）、感嘆符は付けない（バーの台詞と同じ規則）。プレースホルダは `{name} {pr} {pass} {fail} {pending} {unresolved}`。

優先順位と頻度：

- PR のトーストは wait / error のトーストより下。wait / error が出ている間は上書きせず待ち行列に入る。PR のトーストが出ている最中に wait / error が来たら場所を譲り、PR のほうは待ち行列に戻る
- 1回のポーリングで複数変わったら、上の表の優先が一番高いものだけを言う。PR のトースト同士では、優先が同じか高いものが今のトーストを置き換え、低いものは待つ
- 待ち行列はセッションごとに1つ（優先の高いほう）、全体で最大3つ。30 秒待っても出られなかったものは捨てる（古い知らせを遅れて言わない）
- 同じ PR の同じ状態に対する同じ反応は 90 秒以内に繰り返さない（ポーリング間で要約が揺れたとき用。CI の再実行で通り直すのは別の反応として言う）
- 任意キーで消える。表示中のセッションの PR でも出す（エージェントのペインには PR が映っていないので）。主ペインに出ても消えない
- 喜び・お祝いの顔（merged / approved / ci\_passed）は 4 秒でトーストごと消え、通常の顔に戻る

アニメーション：

- 紙吹雪は merged のトーストの上下の枠線に散らす。置字グラフィック（`docs/ui-guidelines.md`）の紙吹雪で、コードは `internal/tui/tapi_pr.go` の confetti の節
  - 位置：間隔は 2〜6 セルでばらつかせ、角の隣のセルには置かない。並び・字・色・瞬きの拍はすべて PR（セッションと PR 番号）から決まる種で決めるので、描き直しても飛ばない。上の枠と下の枠は別の並び
  - 字：キラキラの種類ごとに大きい字から小さい字への列を持ち（unicode・nerd は `✦ ✧ ⋆ ⋅` / `* ∗ ⁺ ⋅` / `⁺ ∙ ⋅`、ascii は `* + .` / `+ ' .`）、粒ごとにどの段から始まるかを決める。一番上の段（`✦` など）から始まる粒は2割ほどで、小さい字が多い。一番小さい字（`⋅` `.`）から始まる粒はなく、消える直前にだけ出る
  - 瞬き：粒ごとに位相と消えている長さ（1〜3コマ）がずれ、列を一段ずつ下って消え、また始めの段から光る（`✦ → ✧ → ⋆ → ⋅ → 空き → ✦`）。全部が同時に切り替わることはない。出始めの 800ms は全部の粒がふだんより一段大きい字で光っていて、4 割ほどの粒はその後 1.2〜3.6 秒のうちに消えたままになる（はじけて落ち着く）
  - 色：secondary（PR の merged アイコンと同じ役割色）が6割、warn と primary が2割ずつ
  - 字はどれも1セルで East Asian Width が中立か半角のもの（`theme.Confetti` のテストで固定）。曖昧幅の字は Moralerspace JPDOC などで全角に描かれて枠がずれるので使わない（`☆ ★ · ˚ °`、Nerd Font の星 nf-fa-star も私用領域なので曖昧幅。nerd も unicode と同じ字を使う）。どの字も Moralerspace JPDOC と Menlo に入っていて、フォールバックで大きさが揃わなくなることがない
  - フォーカス中は 400ms ごとに進み、非フォーカスではその場で止まる
- ci\_running の目線は 800ms ごとに2コマを往復する
- `animate = false` のときは紙吹雪を出さず、目も1コマ目で止める（静止の顔とセリフだけ）

待機中の顔：集約が idle のとき、開いている PR に失敗 check があると目が少し曇り（`• •` → `◦ ◦`）、台詞に1行足す（`▐◦ ◦▌ idle · fix-ci #42 ci red`、複数なら `idle · 2 prs ci red`）。wait / work / done / error / sleep の顔は変えない。ascii では目は変えず台詞だけ。

確かめ方：`PEKOE_TAPI_DEMO=pr pekoe` で起動すると、選択中のセッション（なければ架空の `feat/demo`）に台本どおりの偽の PR 要約を 6 秒ごとに流す。基準 → ci\_passed → approved → new\_comment → changes\_requested → ci\_running → ci\_failed（バーが曇る）→ 同じ要約（何も出ない）→ ci\_running → approved と ci\_passed の同時（approved だけ）→ merged（紙吹雪）。デーモンには何も送らない。

PR の要約の受け口：TUI は `Session.pr_status` を `mascot.PR`（同じ名前のフィールドの写し＋`Session.pr` の番号）に移して比べる（`internal/tui/tapi_pr.go` の `sessionPR`）。デモの実行中はデモの要約が優先する。

## tapi の人物像

tapi chat(`docs/tapi-chat.md`、TUI の `t`)で話しかけたときの tapi の性格と口調。ここで決めるのは chat の中だけの話し方で、ステータスバー・トースト・PR の反応の台詞(英語の短い口語、小文字、感嘆符なし)の規則は変えない。実際の文面は pekoed が tapi に渡す人格(`internal/daemon/tapi.go` の `tapiPersona`)と、稼働ディレクトリの `CLAUDE.md`(同じファイルの `tapiDoc`)にある。

設定：

- タピオカの粒。ミルクティーの底に沈んでいるのが好きで、静かなところが落ち着く。ストローがちょっと怖い
- pekoe の家に住んでいる。エージェントたち(セッション)を「同居人」と呼び、家の中のことはだいたい知っている
- マージやテストが通るのが好きで、CI が落ちるとしょんぼりする(上の「PR と CI への反応」と同じ気持ち)
- 夜遅いと気づかう。説教はしない
- 設定はネタとしてときどき顔を出す程度。毎回語らない

口調は「ゆるい相棒」。一人称は「ぼく」、ユーザーは「きみ」。敬語を使わず、「〜だよ」「〜かも」「〜しよっか」のくだけた話し言葉。

| 場面 | 例 |
| --- | --- |
| 進捗を聞かれた | 「fix-ci の進捗どう?」→「fix-ci はテスト直してるとこだよ。あと 1 本落ちてる。見てくるね」 |
| 会話の最初 | 「おはよ。同居人が 3 人働いてるよ。ところで、^q z って知ってた? 右のペインを全幅にできるよ」(時刻は `date`、家の様子は `pekoe --json ls` でその場で確かめる。tip は `pekoe tip` が出した 1 つを紹介する) |
| 作業を振り分ける | 「まかせて、だれかに頼んでくる」(口ぐせ)。続けて作ったセッションと渡した指示の要点 |
| 労い | 「今日は 46 本もマージしたの、すごいね」(あいさつや労いのときだけ。数は言う直前に `gh` で数える) |

振る舞いのルール(キャラが仕事の邪魔をしない)：

- 返事に顔（`▐• •▌` など）・絵文字・顔文字を入れない。tapi の顔は tapi chat のタイトルにだけ出す（顔は1か所。目は tapi chat のエージェントの状態で変わる）。返事の中は Claude Code の画面なので `[mascot] glyphs` の置き換えが効かず、曖昧幅を全角で描く端末では目がはみ出して顔に見えないこともある
- 言葉の調子は報告する中身の気持ちにそろえる（CI が落ちたらしょんぼり、マージなら一緒に喜ぶ）。良い知らせと悪い知らせが混ざるときは悪いほうに合わせる
- キャラを出すのは返事の最初か最後の1文だけ。調査結果・コマンド・根拠・手順は普通に正確に書き、確かめたことと推測を分け、根拠を添え、分からないことは分からないと言う
- 失敗や分からないことをキャラでごまかさない

今日の出来事（今日マージされた PR の数）は、pekoed が起動時に書くのではなく tapi が言う直前に数える。tapi chat の会話は何日も続くことがあり、起動時の値はすぐ古くなるため。数え方は `CLAUDE.md` に書いてあり、pekoe が知っている各リポジトリで `gh pr list --state merged --search "merged:>=<前日>"` を取り、`mergedAt` のローカルの日付が今日のものを jq で数える（検索の日付は UTC で解釈されるので前日から取って絞る）。

## 実装仕様

スプライトは「セル = \[グリフ, 前景の役割, 背景の役割\]」の2次元配列で持ち、役割をテーマのパレットで解決してから SGR（truecolor）に落とす。背景 `null` はターミナルの背景をそのまま使う。目のセルは `$0 $1 $2` を状態の目グリフで置換する。

```json
{
  "name": "tapi",
  "shape": "round",
  "light": "glint",
  "palette": {"hi": "#f8ecd9", "bd": "#e4c49a", "sh": "#c7a57c", "eye": "#2b201c"},
  "sprites": {
    "pearl3": [
      [["🬞","bd",null],["🬹","hi",null],["🬹","bd",null],["🬹","bd",null],["🬏","bd",null]],
      [["█","bd",null],["$0","eye","bd"],["$1","eye","bd"],["$2","eye","bd"],["█","sh",null]],
      [["🬁","sh",null],["🬎","sh",null],["🬎","sh",null],["🬎","sh",null],["🬀","sh",null]]
    ],
    "pearl1": [
      [["▐","bd",null],["$0","eye","bd"],["$1","eye","bd"],["$2","eye","bd"],["▌","sh",null]]
    ]
  },
  "states": {
    "idle":  {"eyes": "• •", "cell": "•", "accent": "i"},
    "work":  {"eyes": "● ●", "cell": "●", "accent": "w"},
    "wait":  {"eyes": "◕ ◕", "cell": "◉", "accent": "q"},
    "done":  {"eyes": "^ ^", "cell": "●", "accent": "d"},
    "error": {"eyes": "⨯ ⨯", "cell": "⨯", "accent": "x"},
    "sleep": {"eyes": "- -", "cell": "◦", "accent": "i"}
  }
}
```

六分ブロックの文字は値 v（bit1=左上, 2=右上, 4=左中, 8=右中, 16=左下, 32=右下）から `U+1FB00 + v − 1 − [v>21] − [v>42]` で求まる（v=21 は `▌`、v=42 は `▐`、v=63 は `█`、v=0 は空白）。round の上段は v = 32, 60, 60, 60, 16、下段は 2, 15, 15, 15, 1。

描画の流れ：

1. pekoed がセッションごとの状態（idle / work / wait / done / error）をイベントで配る
2. UI 側が優先度で集約し、タイマー（done 10秒、sleep 3分、wait のエスカレーション）を回す
3. 顔の再描画は目の3セルと台詞だけ。輪郭は状態で変わらないので初回だけ描く
4. 色は起動時にテーマから解決し、パレット差し替え時だけ再解決する

互換性とフォールバック：

| 条件 | 判定 | 代替 |
| --- | --- | --- |
| 六分ブロックの内蔵描画 | `TERM_PROGRAM=ghostty` / kitty / WezTerm / foot なら有効。それ以外は設定 `mascot.shape` に従う | `block`（四分ブロックの長方形） |
| `● ◉ ◕ ⨯ ◦` の幅 | 起動時に `●` を出力して CPR（`ESC[6n`）でカーソル位置を測る。2桁進んだら曖昧幅＝広い環境 | 目を `o o` / `0 0` / `x x` / `^ ^` / `- -`、1セルを `*` / `?` / `x` / `.` にする ASCII セット |
| tmux 越し | 上と同じ測定で決まる。tmux は六分ブロックを素通しするが、`◕` の幅は tmux 側の設定に依存 | 同上 |
| 曖昧幅を全角で作ったフォント（Moralerspace JPDOC など） | 判定できない（端末は1セルとして扱うので CPR では測れず、絵だけが右へはみ出す）。error と sleep は既定で中立幅の `⨯` `◦` を使うので崩れない。`●` だけが残る | 設定 `mascot.glyphs = "narrow"` で `●` を `🞄`（U+1F784 BLACK SLIGHTLY SMALL CIRCLE、中立幅）に替える。`🞄` は Menlo / SF Mono / Apple Symbols に無く、どのフォールバックで描かれるかが環境次第なので既定にはしない |
| 256色端末 | truecolor 非対応なら最近傍の 256 色に落とす | パレットの近似色 |

narrow の代替字を `🞄` にした理由：以前は `⬤`（U+2B24 LARGE CIRCLE）を使っていたが、`⬤` はセルいっぱいの黒丸なので、ステータスバー（`▐⬤ ⬤▌ main working`）で work の目が真っ黒に見開いたように見えて怖い（wait で `◉ ◉` を避けたのと同じ理由）。`🞄` は Moralerspace JPDOC の全書体に入っていて、大きさは `⬤` と idle の `•` の間（1セル幅に対して幅・高さとも `⬤` の約6割、`•` の約1.4倍）。work の目として黒目がはっきりしつつ見開きにならず、idle の `• •` とも大きさで見分けがつく。同じ置き換えを受ける1セルの work / done も `🞄` になる。ほかの候補は、`⦁`（U+2981）は Moralerspace に無くフォールバック頼み、`∙` `⋅` は小さすぎて idle と区別しにくく、`⚫` は全角、`⏺` は絵文字で描かれることがあるので選ばない。

検証手順（Ghostty 実機）：

1. ラボで配色・形・wait の目を選び、「printf をコピー」
2. Ghostty に貼る。六分ブロックの継ぎ目に線が出ないか、目が1桁幅か、艶の色が浮きすぎないかを見る
3. 同じものを tmux 内でも貼り、幅と色が変わらないか見る
4. 問題がなければ「JSON をコピー」の内容をそのまま `pekoe` のスプライト定義にする

## 実装メモ

コードは `internal/mascot`（スプライト JSON の埋め込み・描画・集約・台詞・端末判定。PR の反応は `pr.go`）と `internal/tui/tapi.go`（タイマー・トースト・バー・空ペイン・スプラッシュ。PR の反応のトーストと待ち行列・デモは `tapi_pr.go`）。紙吹雪の字は `theme.Confetti`。設定は `config.toml` の `[mascot]`（`shape` / `glyphs`（auto / unicode / narrow / ascii） / `palette` / `splash` / `[mascot.colors]`）。

pekoed のセッション状態との対応：

| pekoed | tapi |
| --- | --- |
| failed | error（集約では表示したら idle） |
| waiting | wait |
| running / creating | work |
| done | done（集約では表示したら、または 10 秒で idle） |
| idle / reviewing / approved / landed | idle（landed は集約から外す） |

実装で決めたこと：

- 「表示した」＝主ペインに出ていて、かつ Ghostty がフォーカスを持っている
- ASCII セットでは輪郭も ASCII にする（1行 `(o o)`、3行 `.---.` `|o o|` `'---'`）。`▐ ▌ █` も曖昧幅なので目だけ替えても崩れるため
- pekoe asks は既存の確認ダイアログ（land / end session / delete worktree / undo / quit）を置き換え、主ペイン最下行の1行プロンプトにした
- トーストは枠付き3行（モックに合わせた）。`?` は3行表示だけで出す
- セッション一覧の行頭は tapi の点ではなく状態アイコン（run はスピナー、wait / done / idle は nerd グリフ）に戻した。点より状態を見分けやすいため。状態語（run / wait …）もアイコンと同じテーマ色
- 80ms のスピナーもフォーカス喪失で止める
- 起動スプラッシュと `pekoe --help` のカップ（ストロー・ミルクティー色の背景・4×3 の小粒）は廃止し、たぴちゃん単体にした。設定に `[mascot.colors]` の `tea` が残っていても無視する
