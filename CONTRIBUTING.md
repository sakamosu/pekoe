# Contributing

## Policy

pekoe is a personal project, and **pull requests are not accepted**. Bug reports and feature requests are welcome as [issues](https://github.com/sakamosu/pekoe/issues). Please report vulnerabilities privately instead, as described in [SECURITY.md](SECURITY.md).

The rest of this file describes how the project is developed and released, for reference. The design docs under `docs/` are in Japanese.

## Development

```sh
make build && make test     # go vet + go test (default and -tags web) + headless nvim tests
```

The Web UI (`internal/daemon/webts.go`) is only in `-tags web` builds. The default build must not pull in Tailscale: nothing but `webts.go` imports `tailscale.com`.

### Trying things in a sandbox

To test or try pekoe without touching your real environment, isolate it with `PEKOE_HOME` (settings and state), `PEKOE_SOCK`, `PEKOE_TMUX_SOCKET` and `PEKOE_WORKTREES`. `scripts/sandbox.sh` sets all four:

```sh
scripts/sandbox.sh                    # start an isolated daemon and drop into a subshell; cleaned up on exit
scripts/sandbox.sh pekoe new feat/x   # run a single command
WEB=1 scripts/sandbox.sh              # with the Web UI build
```

It creates the four in a temporary directory and starts a daemon with a `pekoe` built from the current source (`PEKOE_BIN` points it at a prebuilt binary instead). When it ends, including on failure or Ctrl-C, it stops the tmux server with `pekoe daemon stop --kill-agents --yes` and deletes the temporary directory.

If you set up an isolated environment by hand, clean it up at the end with `pekoe daemon stop --kill-agents --yes` under the same environment variables (`pekoe daemon stop` alone leaves the tmux server and the fake agents behind). The tmux server's pid is recorded at startup in `$PEKOE_HOME/share/tmux-<socket>.pid`, so it can be stopped even when `kill-server` can't reach it (for example with a different `TMUX_TMPDIR`).

- Never use `--kill-agents` with `PEKOE_TMUX_SOCKET` empty or set to `pekoe`: that stops every real agent
- Unix socket paths are limited to about 104 bytes on macOS, so put the isolated directory somewhere short, such as directly under `/tmp`

## Cutting a release

Pushing a `v*` tag makes GitHub Actions (`.github/workflows/release.yml`) cross-build 4 platforms × default / `-tags web` with GoReleaser (`.goreleaser.yaml`), create a release with the archives, `checksums.txt` and a changelog since the previous tag, and attach build provenance (an attestation) to each archive.

- `THIRD_PARTY_LICENSES` in the archives is generated by GoReleaser's `before.hooks` with `scripts/third-party-licenses.sh`, once for the default build and once for `-tags web` (it concatenates the license texts of the modules found by `go list -deps` and of Go itself, and stops if a module has no license file). Its output directory `build/` is not committed
- Builds use only the Go in go.mod's `go` line (`GOTOOLCHAIN=local`). Before building, govulncheck runs with the same Go for the default and `-tags web` builds and stops the release if a known vulnerability is reachable
- `.github/workflows/govulncheck.yml` runs govulncheck for both builds on push, on pull requests and weekly. Locally: `make vulncheck`
- Workflow actions are pinned to commit SHAs and bumped by Dependabot (`.github/dependabot.yml`)
- The version is set from the tag through ldflags and shown by `pekoe version` (a local `make build` uses `git describe`; a plain `go build` gives `dev`)

```sh
git tag vX.Y.Z && git push origin vX.Y.Z
goreleaser release --snapshot --clean   # try it locally (output in dist/; nothing is published)
```

goreleaser is installed from the Go module proxy, both in the workflow and locally (GitHub release asset downloads are sometimes unavailable). Match the version to `GORELEASER_VERSION` in the workflow:

```sh
GOTOOLCHAIN=auto go install github.com/goreleaser/goreleaser/v2@v2.20.0
```
